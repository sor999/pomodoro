# PRD: 뽀모도로 + 집중 세션 로그

- 상태: 초안
- 작성일: 2026-07-31
- 작성자: product-planner

## 1. 문제 / 배경

사용자는 공부·업무 시 집중 시간을 스스로 관리하기 어렵고, "오늘 얼마나 집중했는지"를 파악할 방법이 없다. 기존 뽀모도로 앱들은 타이머 기능만 제공하거나, 통계를 보려면 회원가입·서버 연동이 필요한 경우가 많다.

이 프로젝트는 **백엔드 없이 브라우저 안에서 완결되는** 뽀모도로 타이머를 만들어, 사용자가 집중 세션을 반복 수행하고 그 이력을 로컬에 누적 기록하여 스스로의 집중 패턴을 돌아볼 수 있게 한다. 동시에 `day1-ai` 저장소의 React 19 + TypeScript + shadcn/ui 학습 목적에 맞는, 과하지 않은 초~중급 난이도의 실습 프로젝트 역할을 한다.

## 2. 목표 (Goals)

- 뽀모도로 방식(집중 시간 / 휴식 시간을 번갈아 진행)의 타이머를 브라우저에서 동작시킨다.
- 완료된 집중 세션을 브라우저 로컬 저장소에 기록하고, 새로고침/재방문 후에도 유지한다.
- 누적된 세션 이력을 바탕으로 간단한 통계(오늘/전체 완료 횟수, 총 집중 시간 등)를 보여준다.
- 세션(집중 또는 휴식) 종료 시 사용자에게 알림(Notification API, 불가 시 인앱 알림)으로 알려준다.
- 별도 로그인/서버 없이 한 브라우저 내에서 개인이 바로 사용할 수 있어야 한다.

## 3. 비목표 (Non-goals)

이번 스코프에서 명시적으로 다루지 않는다:

- 사용자 계정/로그인, 서버 동기화, 여러 기기 간 데이터 공유
- 팀/공유 기능 (다른 사용자와 세션 공유, 랭킹 등)
- 상세 리포트(주간/월간 차트, CSV 내보내기, 태그별 분석 등 고급 통계)
- 집중 대상(할 일/프로젝트) 관리 — 세션에 "무엇을 했는지" 텍스트 라벨을 붙이는 것은 Could로 고려하되, 별도의 할 일 관리(Task 목록, 체크리스트) 기능은 다루지 않음
- 커스텀 사운드/백색소음 재생, 테마 커스터마이징(다크 캔버스 외 추가 테마)
- 모바일 앱/PWA 오프라인 설치, 백그라운드(탭이 닫힌 상태) 타이머 동작 보장
- 뽀모도로 사이클 자동 롱브레이크 규칙(예: 4세트마다 15분 휴식) 등 고급 스케줄링 — Should/Could로 최소화

## 4. 핵심 사용자 스토리

1. 사용자로서 나는 버튼 하나로 25분 집중 타이머를 시작하고 싶다, 왜냐하면 시작 설정을 매번 고민하고 싶지 않기 때문이다.
2. 사용자로서 나는 집중 시간이 끝나면 알림을 받고 싶다, 왜냐하면 다른 창을 보고 있어도 세션 종료를 놓치지 않고 싶기 때문이다.
3. 사용자로서 나는 집중 세션이 끝날 때마다 자동으로 기록이 남기를 원한다, 왜냐하면 수동으로 기록하는 번거로움 없이 내 집중 이력을 쌓고 싶기 때문이다.
4. 사용자로서 나는 오늘 몇 번의 뽀모도로를 완료했고 총 몇 분을 집중했는지 한눈에 보고 싶다, 왜냐하면 스스로의 하루 집중량을 파악하고 동기부여를 얻고 싶기 때문이다.
5. 사용자로서 나는 타이머 중간에 세션을 멈추거나 초기화할 수 있어야 한다, 왜냐하면 예상치 못한 방해가 생길 수 있기 때문이다.
6. 사용자로서 나는 브라우저를 껐다 켜도 예전 기록이 남아있길 원한다, 왜냐하면 매번 초기화되면 통계가 의미 없기 때문이다.
7. 사용자로서 나는 집중/휴식 시간 길이를 원하는 값으로 바꾸고 싶다, 왜냐하면 사람마다 적정 집중 시간이 다르기 때문이다.

## 5. 기능 요구사항

우선순위: **Must** (이번 스코프 필수) / **Should** (여유 있으면 포함) / **Could** (다음 기회에)

### 5.1 타이머 (Must)

- 집중 세션(기본 25분)과 휴식 세션(기본 5분)을 순서대로 진행하는 카운트다운 타이머를 제공한다.
- 시작 / 일시정지 / 재개 / 초기화(리셋) 조작을 제공한다.
- 현재 진행 중인 세션의 종류(집중/휴식)와 남은 시간을 화면에 표시한다.
- 세션이 자연 종료(카운트다운이 0에 도달)되면 다음 세션 종류로 자동 전환하거나, 사용자가 다음 세션을 수동으로 시작할 수 있어야 한다(둘 중 하나는 이후 planner/implementer 단계에서 결정 — 이번 기획에서는 "종료 시 사용자가 인지 가능해야 한다"는 요구만 확정).

### 5.2 집중/휴식 시간 커스터마이즈 (Should)

- 사용자가 집중 시간과 휴식 시간 길이를 분 단위로 변경할 수 있다.
- 변경한 값은 다음 세션부터 적용되며, 진행 중인 세션에는 영향을 주지 않는다(또는 초기화 후 적용 — 세부 동작은 planner 단계에서 확정).

### 5.3 세션 기록 저장 (Must)

- 집중 세션이 완료될 때마다(끝까지 진행되어 종료된 경우) 세션 기록 1건이 로컬 저장소에 자동 생성된다.
- 기록에는 최소한 완료 일시와 집중 시간(분)이 포함된다.
- 세션을 중간에 취소/초기화한 경우는 완료 기록으로 남기지 않는다(부분 완료는 이번 스코프에서 기록하지 않음).
- 저장된 기록은 브라우저를 새로고침하거나 재방문해도 유지된다(로컬 저장소 기반, 서버 없음).

### 5.4 통계 대시보드 (Must)

- 오늘 완료한 집중 세션 횟수와 총 집중 시간(분 또는 시간)을 표시한다.
- 누적(전체 기간) 완료 세션 횟수와 총 집중 시간을 표시한다.
- 최근 완료된 세션 목록(날짜/시간, 소요 시간)을 간단한 리스트 형태로 확인할 수 있다.

### 5.5 알림 (Must)

- 집중 세션 종료 시 브라우저 Notification API를 통해 사용자에게 알림을 보낸다.
- 사용자가 알림 권한을 거부했거나 브라우저가 미지원인 경우, 화면 내 시각적 알림(예: 배너, 사운드 등 대체 수단)으로 대체된다 — 알림 자체가 완전히 무시되지 않아야 한다.
- 휴식 세션 종료 시에도 동일한 방식의 알림을 제공한다(Should: 집중 종료만 Must, 휴식 종료 알림은 Should로 취급 가능 — 최소 요구는 "집중 세션 종료 알림"이다).

### 5.6 기록 관리 (Could)

- 사용자가 개별 세션 기록을 삭제할 수 있다.
- 사용자가 전체 기록을 초기화(전체 삭제)할 수 있다.

## 6. 수용 기준 (Acceptance Criteria)

### 타이머
- [ ] 앱 진입 시 기본 집중 시간(25분)이 타이머에 표시된다.
- [ ] "시작"을 누르면 타이머가 1초 단위로 감소하기 시작한다.
- [ ] "일시정지"를 누르면 카운트다운이 멈추고, "재개"를 누르면 멈춘 지점부터 이어서 진행된다.
- [ ] "초기화"를 누르면 현재 세션이 종료되고 타이머가 설정된 초기 시간으로 되돌아가며, 이 경우 세션 기록은 저장되지 않는다.
- [ ] 집중 세션의 카운트다운이 0에 도달하면 해당 세션은 "완료"로 처리되고 기록이 1건 생성된다.

### 커스터마이즈
- [ ] 사용자가 집중/휴식 시간을 원하는 분 단위 값으로 입력하면, 다음 세션 시작 시 해당 값이 반영된다.
- [ ] 잘못된 값(0 이하, 숫자가 아닌 값)을 입력하면 적용되지 않고 이전 값이 유지된다.

### 세션 기록 저장
- [ ] 집중 세션 완료 직후 새로고침해도 방금 완료한 세션 기록이 통계/목록에 남아있다.
- [ ] 세션을 중간에 초기화(리셋)한 경우, 해당 시도는 기록 목록에 나타나지 않는다.
- [ ] 저장된 기록에는 완료 일시와 집중 시간(분)이 포함되어 있다.

### 통계
- [ ] "오늘"의 범위는 로컬 기기의 날짜(자정 기준) 기준으로 계산된다.
- [ ] 오늘 집중 세션을 3회 완료하면, 오늘 완료 횟수가 3으로 표시된다.
- [ ] 전체 누적 완료 횟수와 총 집중 시간이 모든 기록의 합으로 정확히 계산되어 표시된다.
- [ ] 최근 완료된 세션 목록에서 가장 최근 항목이 가장 위(또는 명시된 정렬 규칙)에 표시된다.

### 알림
- [ ] 알림 권한이 허용된 상태에서 집중 세션이 종료되면, 브라우저 Notification이 표시된다.
- [ ] 알림 권한이 거부되었거나 Notification API를 지원하지 않는 환경에서도, 집중 세션 종료 시 화면 내에서 시각적으로 인지 가능한 알림이 표시된다.
- [ ] 다른 탭/창에 포커스가 가 있어도(탭이 열려있는 한) 알림이 정상적으로 도착한다.

## 7. 미해결 질문 / 리스크

- **자동 전환 여부**: 집중 세션 종료 후 휴식 세션이 자동으로 시작되어야 하는지, 사용자가 수동으로 다음 세션을 시작해야 하는지 확정 필요. (5.1 참고)
- **탭이 백그라운드/비활성일 때 타이머 정확도**: 브라우저가 백그라운드 탭의 `setInterval`을 스로틀링할 수 있어, 실제 경과 시간과 표시 시간이 어긋날 수 있음. 허용 오차 범위를 planner 단계에서 결정 필요.
- **탭을 닫은 경우**: 타이머가 진행 중인 상태로 탭을 닫으면 해당 세션은 미완료로 간주하고 폐기하는지, 아니면 재방문 시 이어서 복원하는지 결정 필요 (이번 비목표 범위에서는 복원을 보장하지 않는 쪽을 권장).
- **저장소 선택**: localStorage와 IndexedDB 중 무엇을 쓸지는 기술 구현(How) 영역이므로 planner 단계에서 결정. 단, 데이터 용량이 커져도(예: 수백~수천 건 기록) 성능 저하가 없어야 한다는 제약만 이번 문서에 남긴다.
- **여러 탭에서 동시에 앱을 열었을 때의 동작**(중복 기록, 상태 불일치 가능성)은 이번 스코프에서 별도로 다루지 않으며, 발생 가능한 리스크로만 남긴다.
- **알림 권한 거부 시 UX**: 권한을 요청하는 시점(앱 진입 시 즉시 vs 사용자가 첫 세션을 시작할 때)은 이후 기획 보완 또는 planner 단계에서 결정 필요.

## 8. 향후 고려사항 (이번 스코프 제외)

- 주간/월간 통계 차트, 요일별/시간대별 집중 패턴 분석
- 세션에 "무엇을 했는지" 라벨/태그를 붙이고, 태그별 통계를 보는 기능
- 자동 롱브레이크(예: 4세트마다 긴 휴식) 등 고급 뽀모도로 규칙
- PWA화 및 오프라인 지원, 백그라운드 정확도 보장
- 데이터 내보내기/가져오기(JSON, CSV)
- 사운드/백색소음, 테마 커스터마이징
